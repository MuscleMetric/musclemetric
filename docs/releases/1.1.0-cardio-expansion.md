# MuscleMetric v1.1.0 — Cardio Expansion

**Status:** planned / implementation in progress. **iOS first.**
**Release baseline:** v1.0.8 is awaiting Apple review. This plan does not change or deploy that release.

## Product objective

Make cardio as usable and trustworthy as strength tracking: directly record outdoor runs, see real routes and kilometre splits, understand training trends and recognise personal bests. Support mixed strength/cardio and existing manually logged sessions.

| Capability | Source | Release acceptance |

| Cardio personal-best dashboard | Feedback 2026-10-21 | Fastest verified 1k, 5k, 10k, half marathon and marathon; furthest distance; date and provenance |

| Manual, treadmill and mixed cardio compatibility | Existing cardio sessions + release QA | No GPS required for manual entry; preserve distance, time, and lifting volume; no duplicate saved workouts |
| Run type + optional effort | Owner requirement 2026-11-08 | Every **new completed tracked run** is Easy, Tempo, Intervals, Long Run or Race; post-run RPE 1–10 optional, never guessed |
| Friendly loading, permission and error recovery | Feedback 2026-10-13/26 | Clear offline, permission-denied, poor-signal, saving and retry states |

**Not in v1.1.0:** public route sharing by default, turn-by-turn directions, Garmin/Strava sync, live location sharing, heart-rate inference, coach features. Shareable route preview, running goals and advanced run-effort insights are candidates for a later release, not launch blockers.

## Data contract and design decisions

- `cardio_recordings` is an **additive tracking layer**, separate from the historic workout tables. It is safe for GPS recording to begin before `workout_history` exists.
- `workout_history_id` is optional and uniquely links a finished recording after the existing workout-save path succeeds; cross-owner links are rejected in the database.
- Location coordinates live **only** in `cardio_route_points`, never in `posts`, public snapshots, public profiles or third-party telemetry.
- Completed tracked runs **require** one of: `easy`, `tempo`, `intervals`, `long_run`, `race`. Pending recording does not assume a type. Existing manually logged workouts are not retroactively rejected.
- `effort_rpe` is optional 1–10, entered **after** the run; missing effort is not zero.
- Splits have source `gps` or `manual`, explicit duration/distance and an `is_partial` marker. Estimated benchmark times in current `cardio_prs` are distinct from measured GPS split achievements.
- Route deletion cascades from a recording. Linking to workout history also cascades on workout deletion; deletion and retention policy need UX confirmation before rollout.
- Avoid uploading GPS points continuously when a reliable, owner-scoped local draft is sufficient; upload safely in bounded batches. Precise-location user consent and a privacy-policy review are release gates.
- Coordinates are inherently sensitive; never include them in logs, screenshots uploaded as CI artifacts, Sentry payloads, notifications or exports unless the user explicitly opts in.

## Known risks

- GPS accuracy, background limits, location permission rejection, battery use and device clock discontinuities.
- Offline duplicates, partial uploads, account switching and cleanup of orphaned drafts.
- Existing `cardio_prs` can calculate estimated milestones using a workout's average pace: do not present these as verified segment PBs.
- Database migration ledger and old app versions must be checked before production deployment.
